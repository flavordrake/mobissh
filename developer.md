# MobiSSH developer guide

Building, testing and operating MobiSSH, and the diagnostic and distribution features that a user of a release build may not have. User-facing features are in [README.md](README.md).

## Repository

- `native/`: the Flutter app (layout in [native/README.md](native/README.md)). `native/third_party/flterm/` is the vendored terminal fork that renders through libghostty over FFI.
- `server/index.js`: the companion server, one Node.js process on port 8081 (see below). `server/feedback-store.js` and `server/feedback-guard.js` are shared with `server-feedback/`.
- `server-feedback/`: the feedback service container that `server/index.js` relays uploads to ([docs/feedback-service.md](docs/feedback-service.md)).
- `public/`: served verbatim, no build step: `index.html` (redirects `/` to the install page), `native-feedback.js` and `native-time.js` (loaded by the generated `native.html`), and `termux/` (a logcat crash uploader for Termux).
- `hooks/`: `pre-commit` (eslint and semgrep on staged server JS; enabled by `npm install` through `core.hooksPath`) and `mobissh-bridge.sh` (the Claude Code approval hook).
- `infra/bug-report-worker/`: the Cloudflare Worker that receives bug reports from the Play build.
- `docker/`, `docker-compose.*.yml`: the prod server, the feedback service, the test SSH server and the emulator container.
- `scripts/`: every build, test and ops entry point (reference table at the end).
- `docs/`: specs and research. Files that open with a "History" note describe the retired PWA.

## Release builds versus developer features

| Feature | In a release APK | Gate |
|---|---|---|
| In-app Feedback button (screenshot, logs, traces, Review & Send) | yes | always mounted (`native/lib/main.dart`); endpoint `MOBISSH_FEEDBACK_ENDPOINT`, key `MOBISSH_FEEDBACK_KEY` |
| Repro recording (long-press Feedback: frame burst) | yes | always |
| Telemetry rings (connect, lifecycle, gesture, control-mode, paint and frame stats, scroll and SGR traces) | yes, collected in memory, sent only inside a bug report | none |
| Raw terminal byte traces | no | `MOBISSH_RAW_DIAGNOSTICS=true` (`native/lib/diagnostics/diagnostics_config.dart`) |
| Crash reports, uploaded on next launch or connect | yes, automatic | endpoint hard-coded to the tailnet host (`native/lib/diagnostics/crash_reporter.dart`); currently rejected for lack of the key (#1243) |
| Settings → Advanced (share feedback offline, last crash, the bug-report outbox; force crash upload, connection audit and tmux control mode behind "Show experimental settings", stored in `mobissh.ui.featureFlags`) | yes, collapsed | none |
| Self-update (banner and Settings → About & updates) | sideloaded APK only | `MOBISSH_BUILD` must be set; the Play bundle swaps in `android/app/src/play/AndroidManifest.xml`, which drops the installer permission and provider |
| tmux control mode | yes, opt-in setting, off by default | `kControlModeScrollRenders = false` keeps its scrollback off |
| Body text selection | no | `kBodyTextSelectionEnabled = false`; the gutter is the copy path |
| xterm.dart terminal backend | no (code kept as a fallback, not selectable) | |

The endpoints default to the maintainer's tailnet host (`mobissh.tailbe5094.ts.net`). A release APK installed from GitHub off that tailnet gets no update offers (the check fails quietly) and cannot deliver bug or crash reports.

Compile-time defines, all read with `String/bool.fromEnvironment`:

| Define | Default | Set by |
|---|---|---|
| `MOBISSH_BUILD` | empty (no update offers) | `scripts/native-release-apk.sh` |
| `MOBISSH_FEEDBACK_KEY` | empty | `scripts/native-release-apk.sh`, `scripts/build-release-aab.sh` (from `~/.mobissh/feedback.env`) |
| `MOBISSH_FEEDBACK_ENDPOINT` | tailnet `/api/bug-report` | `scripts/build-release-aab.sh` when `FEEDBACK_ENDPOINT` is set |
| `MOBISSH_UPDATE_MANIFEST_URL` | tailnet `/android-latest.json` | nothing |
| `MOBISSH_RAW_DIAGNOSTICS` | false | nothing |

## The companion server

`server/index.js` serves:

- the install page `native.html` (generated by `scripts/gen-apk-install-page.sh`, which renders `native-release-notes.md` through `scripts/render-release-notes.mjs`) and the published artifacts from `native-dist/`: stamped APKs, the AAB, the macOS zip, `macos-latest.json`, and `android-latest.json` (the self-update manifest written by `scripts/gen-android-latest-json.sh`);
- `/api/bug-report`, `/api/native-crash`, `/api/drop-telemetry`, `/api/gesture-telemetry`: relayed to the feedback service, or stored locally when it is down;
- the Claude Code approval bridge: `/api/approval-gate`, `/api/approval-poll`, `/api/approval-respond`, `/api/approval-mode`, `/api/hook` and the `/events` SSE stream;
- `/version` (build and git hash) and `/clear` (unregisters the retired PWA's service worker on a device that still has it).

Static responses carry `Cache-Control: no-store` and a CSP. It is deployed as the `mobissh-prod` container with built-in Tailscale (`tailscale serve`):

```bash
scripts/deploy-prod.sh            # first deploy, handles the Tailscale auth key
scripts/container-ctl.sh ensure   # rebuild only if the baked git hash is stale
scripts/container-ctl.sh status
docker logs mobissh-prod --tail 50
```

The container copies `public/` and `server/` at build time, so it must be rebuilt after changes. `docker-compose.prod.yml` bind-mounts host paths of the maintainer's dev host for uploads and `native-dist/`; adjust them for another host. `scripts/server-ctl.sh` runs a local copy for headless and infra work only. All containers join the external Docker network `mobissh` and reach each other by DNS name (`test-sshd:22`, `mobissh-prod:8081`), never `localhost`.

### Approval bridge and agent notifications

`hooks/mobissh-bridge.sh` is a Claude Code hook installed on a remote host with `scripts/install-remote-hooks.sh`. It is OFF by default (#1251): unless `MOBISSH_APPROVAL_BRIDGE=1` is set or `~/.claude/mobissh-approval-bridge.enabled` exists, it prints nothing and exits, so Claude Code uses its normal permission flow. `MOBISSH_BRIDGE_URL` overrides the server URL. When enabled, on a permission request it asks `/api/approval-gate`; other events go to `/api/hook`. The gate only waits for a decision when a client is subscribed to `/events`, and the native app does not subscribe, so every request is answered at once with the default mode (`allow` unless `.approval-mode` says otherwise). The hook also answers `allow` when the server is unreachable. Bell notifications, which the app does act on, are set up per agent as in [INTEGRATION.md](INTEGRATION.md).

### Bug reports, repro recordings and telemetry

Uploads land in `test-results/uploads/` on the dev host:

- `scripts/watch-bug-reports.sh` watches for new reports; `scripts/pull-feedback.sh` copies them out of the prod container as a fallback.
- `scripts/assemble-repro.sh` turns a repro frame burst into a video or GIF; `scripts/review-recording.sh` samples frames from any screen recording.
- `scripts/paint-replay.sh` replays a report's byte trace through the terminal renderer.
- `scripts/feedback-ctl.sh` runs the feedback service container; the Play build reports to the Worker in `infra/bug-report-worker/` (deploy with `scripts/deploy-worker-rest.sh` and `scripts/cf-api.sh`, check with `scripts/verify-worker.sh`).

Uploads require the `X-MobiSSH-Key` header and are rate limited (`server/feedback-guard.js`). The key is baked into release builds, so anyone holding the APK can extract it; it limits drive-by traffic, not determined abuse.

The server's stored fields are an allowlist in `saveBugReport` (`server/feedback-store.js`); a field the app sends but that is not named there is dropped. `FEEDBACK_RETENTION_DAYS` (default 0, keep everything) turns on the sweep in `server-feedback/index.js`.

On the device, every bug report goes through the outbox (`native/lib/diagnostics/feedback_outbox.dart`): it is written to `<app documents>/feedback-outbox/` before the POST. One file per report, the suffix is the state:

- `.tmp`: an atomic write in progress, renamed to `.json` when complete;
- `.json`: pending, sent by the next flush;
- `.sending`: claimed by an upload in progress (the rename is the lock);
- `.unconfirmed`: a `.sending` left by a process that died mid-upload. The relay has no idempotency key, so it is kept and never resent automatically (at most once);
- `.rejected`: the relay answered 401/403; kept, never retried;
- `.corrupt`: not valid JSON; kept, never sent.

A 2xx deletes the file; any other failure renames it back to `.json`. Flushes run on launch (`native/lib/main.dart`), on a successful connect (`native/lib/ui/connect_form.dart`) and on resume, with exponential backoff from 30 s to 30 min after a failed flush; Send now in Settings → Advanced → Diagnostics skips the backoff. Caps are 10 reports and 50 MB, enforced by dropping the oldest entries. Only file names and counts are logged.

The settings snapshot a report carries is the allowlist `kSettingsSnapshotKeys` in `native/lib/diagnostics/settings_snapshot.dart`; a new setting is absent from reports until it is named there. It includes `mobissh.files.sort.v1`, whose blob is keyed by `host:port:username` per profile, so those labels reach the server; [docs/PRIVACY.md](docs/PRIVACY.md) says so.

## Build, ship and version

Every Flutter call goes through `scripts/flutter-cmd.sh`. On a host with the fleet build runner (`/home/dev/build-runner`), it sources that runner's `flutter-route.sh`, which sends `flutter analyze`, headless `flutter test` and `flutter build apk` to the fleet buildbox. Release APKs come back unsigned and are signed and verified locally, so the keystore never leaves the dev host. Device and integration tests (`integration_test`, `-d`, `--tags integration`) and every other command run locally, as does everything when `CI=true`. `FLEET_BUILD_REMOTE=1` forces local execution; it is a fallback only, not the normal path. Versions follow [docs/VERSIONING.md](docs/VERSIONING.md): `x.y.z[-STAGE]+B` in `native/pubspec.yaml`, with B a global build ordinal that never resets.

- `scripts/ship-native.sh --message-file F`: bumps B (`scripts/lib/next-build-version.sh`), refuses to ship on doc drift (`scripts/doc-drift.sh --block`) or a full disk (`scripts/lib/disk-guard.sh`), commits, pushes, and runs `scripts/native-release-apk.sh` (release keystore required), which stamps the APK, publishes it to `native-dist/`, regenerates the install page, writes the self-update manifest and announces the build (`scripts/notify-build.sh`).
- `scripts/build-release-aab.sh`: the signed Play bundle ([docs/PLAY_STORE_SUBMISSION.md](docs/PLAY_STORE_SUBMISSION.md)).
- macOS: [native/MAC-BUILD.md](native/MAC-BUILD.md) (`scripts/mac-build-via-hub.sh`, `scripts/dispatch-mac-build.sh`, `scripts/publish-native-macos.sh`, `scripts/render-macos-slot.sh`, the Mac-side `scripts/mac/`). Linux desktop: [native/DESKTOP.md](native/DESKTOP.md) (`scripts/setup-linux-desktop-toolchain.sh`, `scripts/desktop-smoke.sh`).
- Update `native-release-notes.md` each release; its top section is the "What to verify" list on the install page.

### Tagging a release

1. RC: set `native/pubspec.yaml` to `x.y.z-rc.N+B`, ship, tag `native-vx.y.z-rc.N`, and publish a GitHub prerelease with the stamped arm64 APK.
2. Final: set the version to `x.y.z+B` (no stage) and ship once more; the version string is compiled in, so the rc bits cannot simply be re-tagged. Tag `native-vx.y.z` and publish a full release with the stamped APK and, when one exists, the macOS zip.
3. Start the next cycle at `x.y.(z+1)-dev`.

`scripts/gh-ops.sh release TAG --title T --notes-file F --target SHA ASSET...` creates the tag and release. It has no prerelease flag yet.

## Testing

| Tier | Command | Covers |
|---|---|---|
| Fast gate (every commit, and CI) | `scripts/native-fast-gate.sh` | gate 0: version, disk-reclaim and integration-wiring rules, `scripts/test-infra.sh` (`test/infra/` and `server-feedback/test.js` on node:test), `scripts/doc-drift.sh --warn`; then `flutter analyze` and the headless Flutter suite. `--with-acceptance` adds `scripts/native-acceptance.sh` (install and first run on an emulator) |
| Terminal flow | `scripts/terminal-flow-gate.sh` | the two end-to-end terminal flows; required for terminal view, gesture, gutter, copy, detection or flterm changes |
| On-device suite | `scripts/with-fleet-emulator.sh -- scripts/native-integration-suite.sh` | connect/auth, reconnect, SFTP, IPC and lifecycle, judged against `native/integration_test/BASELINE.manifest` |
| Subset | `scripts/integration-subset.sh` | named integration tests over one bridge |
| Coverage | `scripts/coverage-report.sh` | `scripts/native-coverage.sh` plus `scripts/lcov-summary.sh` |
| Device | real hardware | gestures, keyboard, lifecycle; required before merging mobile UX |

`.claude/rules/testing.md` is the controlling contract. Each integration test declares its own fixtures in its header (`// Setup (run FIRST): scripts/...`, `// Teardown ...`, `// Runner: ...`), read by `scripts/lib/integration-fixtures.sh`; `scripts/test-integration-wiring.sh` pins that wiring and the manifest in gate 0.

Test infrastructure:

- Test SSH server: `docker-compose.test.yml` (`testuser`/`testpass`, ed25519 key in `docker/test-sshd/`, tmux with `mouse on`), started by `scripts/test-sshd-up.sh` and `scripts/lib/testsshd-fixture.sh`; `scripts/testsshd-tailnet-bridge.sh` exposes it to tailnet peers.
- Emulator: the fleet emulator is leased with `scripts/with-fleet-emulator.sh`; `scripts/emu-container-ctl.sh` drives the dedicated emulator container; `scripts/emulator-ctl.sh` and `scripts/emulator-maintain.sh` manage a local always-on AVD (`scripts/setup-avd.sh`, `scripts/boot-emulator.sh`, `scripts/emulator-cleanup.sh`). `scripts/native-connect-test.sh` runs one test on the device; `scripts/emu-shot.sh` and `scripts/emu-log.sh` grab a screenshot or logcat; `scripts/ci-reap.sh` sweeps orphaned test infrastructure.
- Fixtures named by test headers: `scripts/cc-attach-setup.sh`, `scripts/cc-capture-setup.sh`, `scripts/cc-exec-switch-setup.sh`, `scripts/cc-scroll-setup.sh`, `scripts/cc-nested-setup.sh` and `scripts/cc-nested-teardown.sh` (tmux control mode), `scripts/deep-link-window-1211-setup.sh`, `scripts/deep-link-acceptance.sh`, `scripts/self-update-1216-setup.sh` and `scripts/self-update-1216-teardown.sh` (with `scripts/gen-self-update-fixture-apks.sh`), `scripts/sftp-bytes-1225-setup.sh` and `scripts/sftp-bytes-1225-teardown.sh` (with `scripts/lib/sftp-cap-proxy.sh`), `scripts/run-kbrace-repro.sh`.
- Diagnostics for terminal work: `scripts/tmux-state-trace.sh` (the real tmux server's state), `scripts/capture-terminal-corpus.sh` and `scripts/capture-tmux-cc.sh` (fixture capture), `scripts/validate-cc-parser.sh` (control-mode parser check), `scripts/native-fork-test.sh` (flterm's own suite), `scripts/vendor-mermaid.sh` (the offline Mermaid bundle).

### Doc drift

`scripts/doc-drift.sh` is the fleet two-direction check: every script something calls must be named in a doc, and every `scripts/` or `docs/` path a doc names must exist. It warns in the fast gate and blocks a ship. Placeholders and history-only names go in `scripts/doc-drift-ignore.txt`, each with a reason.

## Working on the repo with agents

- GitHub operations go through `scripts/gh-ops.sh` and `scripts/gh-file-issue.sh`; raw git from the main checkout through `scripts/run-in-repo.sh`.
- Issues are worked by local develop agents on `bot/issue-N` branches in worktrees (`/develop`, `scripts/bot-branch.sh`, `scripts/rescue-worktree.sh`, `scripts/worktree-cleanup.sh`); `/delegate` classifies (`scripts/delegate-discover.sh`, `scripts/delegate-classify.sh`, `scripts/delegate-fetch-bodies.sh`, `scripts/delegate-failure-analysis.sh`, `scripts/develop-propose.sh`) and `/integrate` gates and merges (`scripts/integrate-discover.sh`, `scripts/integrate-gate.sh`, `scripts/integrate-cleanup.sh`, `scripts/integration-required.sh`). Process and labels: `.claude/process.md`; agent design: [docs/agents.md](docs/agents.md); rules: `.claude/rules/`.
- Development arcs are recorded as TRACEs in `.traces/` (gitignored): `scripts/trace-init.sh`, `scripts/trace-check.sh`, `scripts/trace-audit.sh`, `scripts/trace-file-history.sh`, `scripts/trace-symbol-history.sh`, `scripts/trace-github-search.sh`.
- Disk: `scripts/disk-reclaim.sh` runs from builds, ships, integration and the SessionStart hook (`scripts/disk-guard-hook.sh`); `scripts/test-disk-reclaim.sh` pins its safety rules.
- Security audits: `scripts/security-audit-native.sh` (with `scripts/build-security-context.sh`) for the app, `scripts/security-audit.sh` for semgrep plus AI review diffed against accepted findings, `scripts/codex-review.sh` for a one-off review prompt.
- Skill tooling: `scripts/crystallize-audit.sh`, `scripts/crystallize-test.sh`. Editor integration: `scripts/mcp-dart-lsp.sh`, `scripts/mcp-ts-lsp.sh`.
- Host recovery: `scripts/migration-diagnostics.sh` after moving the dev host; `scripts/extract-git-snapshot.sh` pulls a file from a past commit; `scripts/integration-failure-signatures.sh` prints one failure signature per red integration test; `scripts/review-server.sh` serves test artifacts for review on port 9090.
- Test-only scripts outside the gate: `scripts/test-lcov-summary.sh`, `scripts/test-self-update-play-exclusion.sh` (asserts the Play bundle has no updater, on built artifacts).
